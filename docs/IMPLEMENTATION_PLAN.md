# Manabi Admin 完整设计与开发方案

版本：1.0  
目标项目：Manabi 管理后台  
前端目录：`manabi_admin`  
后端目录：`manabi_api`

---

## 1. 项目目标

开发一个用于维护 Manabi 学习平台的独立管理后台，主要管理：

1. 用户账号
2. JLPT N1–N5 真题
3. 真题题组、题目和选项
4. 阅读与听力材料
5. 图片、音频和字幕
6. 内容质量问题
7. 草稿、审核、发布和版本历史
8. 管理员操作日志

后台必须基于现有 Manabi 数据库和 FastAPI 服务增量开发，不能破坏现有 iOS App API、用户练习、错题和统计数据。

## 2. 现有系统情况

### 2.1 当前技术栈

后端：

- Alembic

- Docker Compose

客户端：

- Manabi iOS App

管理后台：

- React
- TypeScript
- Vite
- Ant Design 5
- Sass
- React Router
- TanStack Query
- Axios

### 2.2 当前内容规模

数据库目前包含：

- JLPT N1–N5
- 约 103 套试卷
- 21 种语义题型
- 词汇、语法、阅读、听力四大分类
- 一万余条题目内容版本
- 一万余条题目出现记录
- 四千余份材料
- 三千余个图片或音频资源
- 导入批次和质量问题记录

记录数包含历史版本和退役数据，不能简单理解为当前可练题目数量。

### 2.3 当前核心数据模型

```text
Exam 试卷
└─ Occurrence 题目在试卷中的出现记录
   ├─ Question 不可变题目内容版本
   │  └─ Option 选项及正确答案
   ├─ Material 阅读或听力材料
   │  ├─ 阅读原文
   │  ├─ 翻译
   │  ├─ 字幕
   │  ├─ Audio Asset
   │  └─ Image Asset
   ├─ QuestionType 语义题型
   └─ GroupKey 题组标识
```

关键原则：

- `Question` 表示不可变内容版本。
- `Occurrence` 表示该题在某套试卷中的位置。
- 同一内容可以出现在不同试卷中。
- 阅读和听力的多道题可以共享同一份材料。
- `PracticeItem.snapshot` 保存用户开始练习时的快照。
- 后台更新内容不能修改已有练习快照。
- 已进入练习和错题记录的数据不能物理删除。

## 3. 总体设计原则

### 3.1 以试卷作为业务维护边界

管理员的操作路径是：

```text
试卷 → 科目 → 题型 → 题组 → 题目
```

后台界面不直接向普通编辑人员暴露底层 `occurrence`、内容摘要等技术概念。

### 3.2 以版本作为发布边界

已发布题目、材料和选项禁止原地修改。

修改流程：

```text
已发布内容
    ↓
创建草稿
    ↓
编辑与自动保存
    ↓
内容校验
    ↓
提交审核
    ↓
审核通过
    ↓
发布新版本
```

发布后：

- 已开始的练习继续使用旧快照。
- 新练习使用新版本。
- 历史版本可以查看。
- 必须记录修改人、时间和修改原因。
- 必须能够回滚，但回滚本质上也是发布一个新版本。

### 3.3 材料使用 Copy-on-write

`Material` 在数据库底层可以被多个题组引用，但后台默认把它表现为当前题组的材料。

编辑共享材料时：

1. 检查引用数量。
2. 如果只有当前题组引用，可建立材料新版本。
3. 如果存在多个引用，默认复制材料。
4. 仅将当前题组切换到新材料版本。
5. 高级管理员才可以选择同步修改全部引用。

不能直接修改公共材料记录。

### 3.4 删除应优先使用软删除

- 草稿且未被引用：可以物理删除。
- 已发布试卷：只能下架或归档。
- 已被练习引用的题目：只能退役。
- 用户存在练习数据：只能禁用或匿名化，不能直接删除。
- 媒体存在引用：不能删除。
- 删除和退役必须有二次确认与操作日志。

- 白色和浅灰背景
- 蓝紫色品牌主色
- 大圆角卡片
- 清晰留白
- 轻边框和柔和阴影
- 简洁的状态标签
- 卡片式题目预览
- 易读的中文和日文排版
- 后台信息密度适中
- 桌面端优先，兼容平板

### 4.2 主题方案

Ant Design 5 使用 `ConfigProvider` 和 Design Token 管理组件主题。

建议颜色：

Sass 用于：

- 页面布局

## 5. 权限设计

第一期采用简单角色模型：

### 5.1 超级管理员

- 管理管理员账号
- 管理普通用户
- 编辑和发布内容
- 修改共享资源
- 查看操作日志
- 执行高风险操作

### 5.2 内容管理员

- 查看试卷
- 创建和编辑草稿
- 上传媒体
- 提交审核
- 不能最终发布
- 不能管理用户

### 5.3 审核管理员

- 查看草稿差异
- 通过或退回审核
- 发布或下架内容
- 不能管理用户权限

### 5.4 用户管理员

- 查看和管理普通用户
- 重置密码
- 禁用账号
- 不能编辑真题内容

初期如果不实现完整 RBAC，可以继续使用 `is_admin`，但数据库和接口设计应预留角色扩展。

所有权限必须由后端验证，不能只依赖前端菜单隐藏。

## 8. 功能模块

# 8.1 管理员登录

功能：

- 账号密码登录
- 检查 `is_admin` 或管理员角色
- 恢复登录状态
- 退出登录
- 401 自动清理本地会话
- 普通用户登录后拒绝进入后台
- 跳回登录前目标页面

接口：

```text
POST /api/v1/auth/login
GET  /api/v1/me
POST /api/v1/auth/logout
```

前端要求：

- 不在日志中打印密码或 token
- token 暂时沿用现有认证方案
- 页面刷新后调用 `/me`
- 登录错误显示中文友好提示
- 不能根据英文错误文本实现业务判断

验收：

- 管理员能登录并刷新恢复
- 普通用户不能进入
- 无效 token 自动退出
- 退出后不能访问受保护路由

# 8.6 题目编辑器

字段：

- 题型
- 题干
- 选项
- 正确答案
- 解析
- 位置
- 状态

富文本支持：

- 纯文本
- 段落
- 粗体
- 下划线
- Ruby 注音
- 表格
- 日文全角空格
- 安全 HTML 预览

编辑器保存时不能接受任意脚本、事件属性或不安全 HTML。

选项规则：

- 当前真题通常为 3 或 4 个选项

- 删除选项时必须重新校验答案
- 不允许保存空选项

句子排序题仍按当前数据库结构兼容，不要擅自改变 App 返回协议。


- 允许字幕间存在空白
- 重叠字幕产生警告，不一定阻断发布
- 无效时间产生阻断错误

# 8.9 媒体资源

支持：

- 图片上传
- 音频上传
- 文件预览
- MIME 类型检查
- 文件大小检查
- SHA-256 哈希
- 引用数量
- 上传时间
- 上传管理员
- 孤立资源筛选

建议状态：

```text
uploading
processing
ready
failed
quarantined
```

安全要求：

- 不接受由文件名决定的存储路径
- 文件名不能路径穿越
- 服务端判断真实 MIME 类型
- 上传后生成哈希
- 不直接覆盖原文件
- 有引用的资源不能物理删除
- 不在 API 中暴露宿主机绝对路径

# 8.10 草稿系统

建议增加表：

## content_drafts

字段建议：

```text
id
entity_type
entity_id
exam_id
base_revision_id
payload
status
created_by
updated_by
created_at
updated_at
submitted_at
reviewed_at
reviewed_by
review_comment
version
```

状态：

```text
editing
submitted
approved
rejected
published
discarded
```

规则：

- 一个实体可以有多个历史草稿。
- 同一实体同时只允许一个主要编辑草稿。
- 使用乐观锁 `version` 防止覆盖他人修改。
- 保存时客户端提交当前 `version`。
- 版本冲突返回 409。
- 草稿 payload 必须经过 schema 校验。
- 草稿不影响 iOS App 正式内容。

# 8.14 发布流程

发布必须执行：

1. 锁定草稿和目标试卷。
2. 检查草稿状态。
3. 检查审核权限。
4. 运行完整内容校验。
5. 阻止存在 error 的内容发布。
6. 为题目生成新的不可变版本。
7. 为选项生成新记录。
8. 为材料生成新版本。
9. 更新对应 occurrence 引用。
10. 创建 revision。
11. 更新试卷发布状态。
12. 写入操作日志。
13. 在同一事务中提交。

任何一步失败，整个发布事务回滚。

发布接口建议：

```text
POST /api/v1/admin/drafts/{draft_id}/submit
POST /api/v1/admin/drafts/{draft_id}/approve
POST /api/v1/admin/drafts/{draft_id}/reject
POST /api/v1/admin/drafts/{draft_id}/publish
POST /api/v1/admin/revisions/{revision_id}/rollback
```

## 10. API 通用规范

### 10.1 分页

请求：

```text
limit
offset
```

响应：

```json
{
  "items": [],
  "total": 0,
  "limit": 20,
  "offset": 0
}
```

### 10.2 排序

建议使用：

```text
sort=created_at
order=desc
```

后端必须使用字段白名单，不能直接拼接 SQL 字段。

### 10.3 错误响应

保持兼容 FastAPI：

```json
{
  "detail": "错误说明"
}
```

对于后台业务冲突，可以逐步扩展为：

```json
{
  "detail": {
    "code": "DRAFT_VERSION_CONFLICT",
    "message": "内容已被其他管理员修改",
    "context": {}
  }
}
```

前端逻辑依赖 `code`，不要依赖英文 message。

### 10.4 常见状态码

```text
200 查询或修改成功
201 创建成功
204 删除或无正文操作成功
400 请求语义错误
401 未登录或 token 失效
403 权限不足
404 资源不存在
409 状态或版本冲突
413 上传文件过大
422 参数校验失败
429 请求过于频繁
```

### 10.5 幂等性

以下操作需要幂等处理：

- 发布
- 批量导入
- 文件上传确认
- 密码重置提交
- 高风险批量操作

## 13. 数据迁移原则

所有数据库结构变更必须通过 Alembic。

迁移要求：

- 不修改历史 migration 文件。
- 每个新功能使用新的 migration。
- 先添加兼容字段，再迁移数据，再启用约束。
- 大表迁移避免长时间锁表。
- 新字段先允许空值或提供服务端默认值。
- 生产迁移前备份数据库。
- migration 必须支持测试环境执行。
- 如果 downgrade 会导致数据丢失，要明确说明。

## 14. 安全要求

- 管理接口必须校验管理员身份。
- 敏感操作必须二次确认。
- 密码继续使用安全摘要，不能保存明文。
- 重置密码后建议撤销旧 token。
- 禁用用户后旧 token 必须失效。
- 上传文件必须验证 MIME、大小和路径。
- 富文本必须服务端清理。
- 查询参数必须经过校验。
- 排序字段必须白名单化。
- 操作日志不得包含秘密信息。
- 登录和密码重置需要限流。
- 管理后台生产环境必须使用 HTTPS。
- CORS 只能允许明确的管理后台域名。
- 后台不能暴露数据库、磁盘绝对路径或内部异常堆栈。
